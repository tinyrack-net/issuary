title: Password Authentication
description: Configure password-based authentication in Tinyrack Auth
---

Password authentication is the traditional email/password login method. Tinyrack Auth provides secure password handling with optional email verification and two-factor authentication.

## Configuration

```yaml
basic_authentication_methods:
  password:
    enabled: true
    email_verification: true
    second_factor:
      required: false
    totp:
      enabled: true
      issuer: My App
```

## Options

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `enabled` | boolean | `true` | Enable password authentication |
| `email_verification` | boolean | `true` | Require email verification before login |
| `second_factor.required` | boolean | `false` | Require 2FA setup after registration |
| `totp.enabled` | boolean | `false` | Allow TOTP as second factor |
| `totp.issuer` | string | `Tinyrack` | Issuer name shown in authenticator apps |

## Email Verification

When `email_verification` is enabled:

1. User registers with email and password
2. Verification email is sent
3. User must click verification link before logging in
4. Unverified users cannot access the application

### Verification Flow

```
User Registers
     │
     ▼
Verification Email Sent
     │
     ▼
User Clicks Link
     │
     ▼
Email Verified ──► Login Allowed
```

### Disabling Email Verification

For development or internal applications:

```yaml
basic_authentication_methods:
  password:
    enabled: true
    email_verification: false
```

:::caution
Disabling email verification allows anyone to create accounts with any email address. Only disable this for trusted environments.
:::

## Second Factor Requirement

Force users to set up 2FA after registration:

```yaml
basic_authentication_methods:
  password:
    enabled: true
    second_factor:
      required: true
    totp:
      enabled: true
```

When `second_factor.required` is `true`:

1. User completes registration
2. User is redirected to 2FA setup
3. User must configure TOTP or passkey
4. Only then can they access the application

## Password Security

Tinyrack Auth implements industry-standard password security:

### Password Hashing

- Uses **Argon2** algorithm (winner of Password Hashing Competition)
- Automatic salt generation
- Configurable memory and iteration parameters

### Password Requirements

The default password policy requires:

- Minimum 8 characters
- At least one uppercase letter
- At least one lowercase letter
- At least one number

## API Endpoints

### Registration

```http
POST /api/v1/auth/register
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "SecurePassword123"
}
```

### Login

```http
POST /api/v1/auth/login
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "SecurePassword123"
}
```

### Password Reset Request

```http
POST /api/v1/auth/password/forgot
Content-Type: application/json

{
  "email": "user@example.com"
}
```

### Password Reset

```http
POST /api/v1/auth/password/reset
Content-Type: application/json

{
  "token": "reset-token-from-email",
  "password": "NewSecurePassword123"
}
```

## User Password Management

Authenticated users can manage their passwords:

### Update Password

```http
PUT /api/v1/user/password
Content-Type: application/json

{
  "currentPassword": "OldPassword123",
  "newPassword": "NewPassword456"
}
```

### Add Password (for social login users)

Users who signed up via social login can add a password:

```http
POST /api/v1/user/password
Content-Type: application/json

{
  "password": "NewPassword123"
}
```

### Remove Password

Users with other authentication methods can remove their password:

```http
DELETE /api/v1/user/password
Content-Type: application/json

{
  "password": "CurrentPassword123"
}
```

## Best Practices

1. **Enable email verification** in production
2. **Consider requiring 2FA** for sensitive applications
3. **Use HTTPS** to protect credentials in transit
4. **Implement rate limiting** to prevent brute force attacks
5. **Monitor failed login attempts** for security incidents
