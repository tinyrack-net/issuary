Tinyrack Auth supports social login (OAuth authentication) with Google, GitHub, Apple, and custom OAuth providers.

## Supported Providers

| Provider | Type | Pre-configured |
|----------|------|----------------|
| Google | `google` | Yes |
| GitHub | `github` | Yes |
| Apple | `apple` | Yes |
| Custom | `generic_oauth` | Manual configuration |

## Configuration

Social login providers are configured in the `oauth_authentication_methods` section:

```yaml
oauth_authentication_methods:
  - type: google
    id: google
    enabled: true
    client_id: !env GOOGLE_CLIENT_ID
    client_secret: !env GOOGLE_CLIENT_SECRET
```

## Google Setup

### 1. Create Google OAuth Credentials

1. Go to [Google Cloud Console](https://console.cloud.google.com/)
2. Create or select a project
3. Navigate to **APIs & Services** > **Credentials**
4. Click **Create Credentials** > **OAuth client ID**
5. Select **Web application**
6. Add authorized redirect URI:
   ```
   https://your-domain.com/api/v1/oauth/google/callback
   ```

### 2. Configure Tinyrack Auth

```yaml
oauth_authentication_methods:
  - type: google
    id: google
    enabled: true
    display_name: Google
    client_id: !env GOOGLE_CLIENT_ID
    client_secret: !env GOOGLE_CLIENT_SECRET
    scopes:
      - openid
      - email
      - profile
```

## GitHub Setup

### 1. Create GitHub OAuth App

1. Go to [GitHub Developer Settings](https://github.com/settings/developers)
2. Click **New OAuth App**
3. Set **Authorization callback URL**:
   ```
   https://your-domain.com/api/v1/oauth/github/callback
   ```

### 2. Configure Tinyrack Auth

```yaml
oauth_authentication_methods:
  - type: github
    id: github
    enabled: true
    display_name: GitHub
    client_id: !env GITHUB_CLIENT_ID
    client_secret: !env GITHUB_CLIENT_SECRET
    scopes:
      - user:email
```

## Apple Setup

### 1. Create Apple Sign In Credentials

1. Go to [Apple Developer Portal](https://developer.apple.com/)
2. Navigate to **Certificates, Identifiers & Profiles**
3. Create an **App ID** with Sign In with Apple capability
4. Create a **Services ID** for your web app
5. Configure the **Web Domain** and **Return URLs**:
   ```
   https://your-domain.com/api/v1/oauth/apple/callback
   ```

### 2. Configure Tinyrack Auth

```yaml
oauth_authentication_methods:
  - type: apple
    id: apple
    enabled: true
    display_name: Apple
    client_id: !env APPLE_CLIENT_ID
    client_secret: !env APPLE_CLIENT_SECRET
    response_mode: form_post
```

:::note
Apple uses `form_post` response mode by default, which is automatically configured.
:::

## Generic OAuth Provider

For custom OAuth providers not pre-configured:

```yaml
oauth_authentication_methods:
  - type: generic_oauth
    id: my-provider
    enabled: true
    display_name: My Provider
    icon_url: https://example.com/icon.png
    client_id: !env MY_PROVIDER_CLIENT_ID
    client_secret: !env MY_PROVIDER_CLIENT_SECRET
    authorization_url: https://provider.com/oauth/authorize
    token_url: https://provider.com/oauth/token
    userinfo_url: https://provider.com/api/userinfo
    scopes:
      - openid
      - email
      - profile
    userinfo_mapping:
      id: sub
      email: email
      email_verified: email_verified
      name: name
      picture: avatar_url
```

### Required Fields for Generic OAuth

| Field | Description |
|-------|-------------|
| `authorization_url` | OAuth authorization endpoint |
| `token_url` | Token exchange endpoint |
| `userinfo_url` | User info endpoint (can be null for JWT tokens) |
| `scopes` | Required scopes to request |
| `userinfo_mapping` | Field mapping from provider response |

### Userinfo Mapping

Map provider-specific fields to standard fields:

```yaml
userinfo_mapping:
  id: sub              # User identifier
  email: email         # Email address
  email_verified: verified  # Optional: email verification status
  name: display_name   # Optional: display name
  picture: avatar      # Optional: profile picture URL
```

## Email Conflict Strategy

When a user signs in with social login using an email that already exists:

```yaml
oauth_authentication_methods:
  - type: google
    id: google
    email_conflict_strategy: auto_link  # or 'require_link'
```

| Strategy | Behavior |
|----------|----------|
| `auto_link` | Automatically link to existing account |
| `require_link` | Require user to authenticate existing account first |

## Common Options

All OAuth providers support these options:

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Unique identifier for this provider |
| `type` | string | Provider type |
| `enabled` | boolean | Enable/disable this provider |
| `display_name` | string | Name shown in UI |
| `icon_url` | string | Icon URL for UI |
| `client_id` | string | OAuth client ID |
| `client_secret` | string | OAuth client secret |
| `scopes` | string[] | OAuth scopes to request |
| `email_conflict_strategy` | string | How to handle email conflicts |

## API Endpoints

### Initiate OAuth Flow

```http
GET /api/v1/oauth/:provider/authorize
```

Redirects user to the OAuth provider's authorization page.

### OAuth Callback

```http
GET /api/v1/oauth/:provider/callback
```

Handles the OAuth callback from the provider.

### Unlink OAuth Account

```http
DELETE /api/v1/oauth/:provider
```

Removes the link between user's account and OAuth provider.

### List Connected Accounts

```http
GET /api/v1/user/oauth-accounts
```

Returns list of connected OAuth providers for the current user.

## Troubleshooting

### "Redirect URI mismatch"

Ensure the callback URL in your OAuth provider settings exactly matches:
```
https://your-domain.com/api/v1/oauth/{provider}/callback
```

### "Invalid client" Error

Verify your client ID and client secret are correct.

### Email Not Returned

Some providers require additional scopes for email access:
- Google: `email` scope
- GitHub: `user:email` scope

### Apple Sign In Issues

1. Ensure Services ID is configured correctly
2. Verify domain verification is complete
3. Check that `response_mode: form_post` is set
