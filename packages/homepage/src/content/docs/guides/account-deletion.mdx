---
title: Account Deletion
description: Configure user account deletion and data retention
---

Tinyrack Auth supports user-initiated account deletion with configurable retention periods for compliance with data protection regulations.

## Configuration

```yaml
account_deletion:
  enabled: true
  retention_period: 30d
```

## Options

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `enabled` | boolean | `false` | Allow users to delete their accounts |
| `retention_period` | string | `30d` | Time before permanent deletion |

## Retention Period Format

The retention period accepts various formats:

| Format | Example | Description |
|--------|---------|-------------|
| Days | `30d` | 30 days |
| Hours | `24h` | 24 hours |
| Minutes | `60m` | 60 minutes |

```yaml
account_deletion:
  enabled: true
  retention_period: 30d  # 30 days
```

## Deletion Flow

When a user requests account deletion:

```
User Requests Deletion
         │
         ▼
Account Marked for Deletion
(soft delete with timestamp)
         │
         ▼
Retention Period Starts
(user can recover account)
         │
         ▼
After Retention Period
         │
         ▼
Permanent Deletion
(all data removed)
```

## Soft Delete vs Hard Delete

### Soft Delete (During Retention)

During the retention period:
- Account is marked as `deleted_at` with timestamp
- User cannot log in
- Data is retained but inaccessible
- User can contact support to recover account

### Hard Delete (After Retention)

After the retention period:
- All user data is permanently removed
- Associated OAuth accounts are unlinked
- Passkeys are deleted
- TOTP secrets are removed
- Consent records are deleted
- Account cannot be recovered

## API Endpoints

### Request Account Deletion

```http
DELETE /api/v1/user
Content-Type: application/json

{
  "password": "current-password"
}
```

The password is required to confirm the deletion request.

### Response

```json
{
  "message": "Account scheduled for deletion",
  "deletedAt": "2024-01-15T10:00:00Z",
  "permanentDeletionAt": "2024-02-14T10:00:00Z"
}
```

## User Experience

### Deletion Confirmation

Users should be shown:

1. What data will be deleted
2. The retention period
3. How to recover their account
4. Confirmation that this action is irreversible after retention

### Deletion Warning Example

```
Are you sure you want to delete your account?

This will permanently delete:
- Your profile information
- All connected OAuth accounts (Google, GitHub, etc.)
- Your passkeys and 2FA settings
- Your consent records

Your account will be recoverable for 30 days.
After that, all data will be permanently deleted.

[Cancel] [Delete My Account]
```

## Data Removed on Deletion

The following data is removed:

| Data Type | Soft Delete | Hard Delete |
|-----------|-------------|-------------|
| User profile | Marked deleted | Removed |
| Email | Retained | Removed |
| Password hash | Retained | Removed |
| OAuth accounts | Retained | Unlinked/Removed |
| Passkeys | Retained | Removed |
| TOTP secrets | Retained | Removed |
| Recovery codes | Retained | Removed |
| Consent records | Retained | Removed |
| Sessions | Invalidated | Removed |
| Refresh tokens | Revoked | Removed |

## Recovery During Retention

To allow account recovery during the retention period:

1. User contacts support
2. Admin verifies user identity
3. Admin removes the `deleted_at` flag
4. User can log in again

:::note
There is no self-service recovery. Users must contact support.
:::

## Compliance Considerations

### GDPR (EU)

- Users have the "right to be forgotten"
- 30-day retention period is reasonable
- Provide clear information about data deletion
- Allow data export before deletion

### CCPA (California)

- Consumers can request deletion of personal information
- Business must delete within 45 days
- Must verify consumer identity

### Recommended Settings

For GDPR compliance:

```yaml
account_deletion:
  enabled: true
  retention_period: 30d
```

## Disabling Account Deletion

For internal applications where account deletion isn't needed:

```yaml
account_deletion:
  enabled: false
```

When disabled:
- The delete account option is hidden in the UI
- The API endpoint returns 403 Forbidden
- Admins can still delete accounts via database

## Background Processing

Account deletion requires background processing for:

1. Scheduling permanent deletion
2. Cleaning up associated data
3. Notifying external systems (webhooks)

Ensure your deployment includes the background job processor.

## Best Practices

1. **Enable deletion for user-facing apps** - Respect user rights
2. **Use appropriate retention** - 30 days is standard
3. **Provide clear UI** - Users should understand consequences
4. **Offer data export** - Before deletion, let users export data
5. **Log deletion requests** - For audit compliance
6. **Test recovery process** - Ensure support can recover accounts
7. **Document for support** - Train support team on recovery process
