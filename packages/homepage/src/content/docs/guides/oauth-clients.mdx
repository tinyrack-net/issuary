OAuth clients are applications that use Tinyrack Auth for user authentication. This guide explains how to register and configure OAuth clients.

## Understanding OAuth Clients

An OAuth client is any application that wants to authenticate users through Tinyrack Auth. Each client is assigned:

- **Client ID** - A unique public identifier
- **Client Secret** - A confidential key for server-side applications
- **Redirect URIs** - Allowed callback URLs after authentication

## Configuring Clients

### Via Configuration File

Add OAuth clients in your `config.yaml`:

```yaml
providers:
  - id: my-web-app
    client_id: my-app-client-id
    client_secret: !env MY_APP_CLIENT_SECRET
    redirect_uris:
      - http://localhost:3000/callback
      - https://myapp.example.com/callback
    scopes:
      - openid
      - profile
      - email
```

### Client Types

#### Public Clients

For single-page applications (SPAs) or mobile apps that cannot securely store secrets:

```yaml
providers:
  - id: my-spa
    client_id: spa-client-id
    # No client_secret for public clients
    redirect_uris:
      - http://localhost:3000/callback
    grant_types:
      - authorization_code
    # PKCE is required for public clients
```

#### Confidential Clients

For server-side applications that can securely store secrets:

```yaml
providers:
  - id: my-backend
    client_id: backend-client-id
    client_secret: !env BACKEND_CLIENT_SECRET
    redirect_uris:
      - https://api.example.com/auth/callback
    grant_types:
      - authorization_code
      - refresh_token
```

## Scopes

Tinyrack Auth supports the following scopes:

| Scope | Description |
|-------|-------------|
| `openid` | Required for OIDC. Returns an ID token |
| `profile` | Access to user's profile information (name, etc.) |
| `email` | Access to user's email address |
| `offline_access` | Receive a refresh token for long-lived access |

## Authorization Flow

1. Client redirects user to authorization endpoint
2. User authenticates and grants consent
3. Auth server redirects back with authorization code
4. Client exchanges code for tokens

```
┌──────────┐                              ┌──────────────┐
│  Client  │──(1) Authorization Request──>│ Tinyrack Auth│
└──────────┘                              └──────────────┘
     │                                           │
     │                                           v
     │                                    ┌──────────────┐
     │                                    │    User      │
     │                                    │ Authenticates│
     │                                    └──────────────┘
     │                                           │
     │<──────(2) Authorization Code──────────────┘
     │
     │──────(3) Token Request───────────────────>│
     │<─────(4) Access Token + ID Token──────────┘
```
