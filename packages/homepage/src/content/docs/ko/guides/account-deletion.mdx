Tinyrack Auth는 데이터 보호 규정 준수를 위해 설정 가능한 보존 기간과 함께 사용자 시작 계정 삭제를 지원합니다.

## 설정

```yaml
account_deletion:
  enabled: true
  retention_period: 30d
```

## 옵션

| 필드 | 타입 | 기본값 | 설명 |
|------|------|--------|------|
| `enabled` | boolean | `false` | 사용자가 계정을 삭제할 수 있도록 허용 |
| `retention_period` | string | `30d` | 영구 삭제 전 시간 |

## 보존 기간 형식

보존 기간은 다양한 형식을 허용합니다:

| 형식 | 예제 | 설명 |
|------|------|------|
| 일 | `30d` | 30일 |
| 시간 | `24h` | 24시간 |
| 분 | `60m` | 60분 |

```yaml
account_deletion:
  enabled: true
  retention_period: 30d  # 30일
```

## 삭제 흐름

사용자가 계정 삭제를 요청하면:

```
사용자가 삭제 요청
         │
         ▼
계정이 삭제 표시됨
(타임스탬프와 함께 소프트 삭제)
         │
         ▼
보존 기간 시작
(사용자가 계정 복구 가능)
         │
         ▼
보존 기간 후
         │
         ▼
영구 삭제
(모든 데이터 제거)
```

## 소프트 삭제 vs 하드 삭제

### 소프트 삭제 (보존 기간 동안)

보존 기간 동안:
- 계정이 타임스탬프와 함께 `deleted_at`으로 표시
- 사용자가 로그인할 수 없음
- 데이터가 유지되지만 접근 불가
- 사용자가 지원팀에 연락하여 계정 복구 가능

### 하드 삭제 (보존 기간 후)

보존 기간 후:
- 모든 사용자 데이터가 영구적으로 제거
- 연결된 OAuth 계정이 연결 해제
- 패스키가 삭제
- TOTP 시크릿이 제거
- 동의 기록이 삭제
- 계정을 복구할 수 없음

## API 엔드포인트

### 계정 삭제 요청

```http
DELETE /api/v1/user
Content-Type: application/json

{
  "password": "현재-비밀번호"
}
```

삭제 요청을 확인하려면 비밀번호가 필요합니다.

### 응답

```json
{
  "message": "계정 삭제가 예약되었습니다",
  "deletedAt": "2024-01-15T10:00:00Z",
  "permanentDeletionAt": "2024-02-14T10:00:00Z"
}
```

## 사용자 경험

### 삭제 확인

사용자에게 다음을 표시해야 합니다:

1. 어떤 데이터가 삭제되는지
2. 보존 기간
3. 계정 복구 방법
4. 보존 후 이 작업은 되돌릴 수 없음 확인

### 삭제 경고 예제

```
계정을 삭제하시겠습니까?

다음이 영구적으로 삭제됩니다:
- 프로필 정보
- 모든 연결된 OAuth 계정 (Google, GitHub 등)
- 패스키 및 2FA 설정
- 동의 기록

계정은 30일 동안 복구 가능합니다.
그 후 모든 데이터가 영구적으로 삭제됩니다.

[취소] [내 계정 삭제]
```

## 삭제 시 제거되는 데이터

다음 데이터가 제거됩니다:

| 데이터 타입 | 소프트 삭제 | 하드 삭제 |
|------------|-----------|----------|
| 사용자 프로필 | 삭제 표시 | 제거 |
| 이메일 | 유지 | 제거 |
| 비밀번호 해시 | 유지 | 제거 |
| OAuth 계정 | 유지 | 연결 해제/제거 |
| 패스키 | 유지 | 제거 |
| TOTP 시크릿 | 유지 | 제거 |
| 복구 코드 | 유지 | 제거 |
| 동의 기록 | 유지 | 제거 |
| 세션 | 무효화 | 제거 |
| 리프레시 토큰 | 폐기 | 제거 |

## 보존 기간 중 복구

보존 기간 동안 계정 복구를 허용하려면:

1. 사용자가 지원팀에 연락
2. 관리자가 사용자 신원 확인
3. 관리자가 `deleted_at` 플래그 제거
4. 사용자가 다시 로그인 가능

:::note
셀프 서비스 복구는 없습니다. 사용자는 지원팀에 연락해야 합니다.
:::

## 규정 준수 고려사항

### GDPR (EU)

- 사용자에게 "잊힐 권리"가 있음
- 30일 보존 기간이 합리적
- 데이터 삭제에 대한 명확한 정보 제공
- 삭제 전 데이터 내보내기 허용

### CCPA (캘리포니아)

- 소비자가 개인 정보 삭제를 요청할 수 있음
- 비즈니스는 45일 이내에 삭제해야 함
- 소비자 신원 확인 필수

### 권장 설정

GDPR 준수를 위해:

```yaml
account_deletion:
  enabled: true
  retention_period: 30d
```

## 계정 삭제 비활성화

계정 삭제가 필요 없는 내부 애플리케이션용:

```yaml
account_deletion:
  enabled: false
```

비활성화되면:
- 계정 삭제 옵션이 UI에서 숨겨짐
- API 엔드포인트가 403 Forbidden 반환
- 관리자는 여전히 데이터베이스를 통해 계정 삭제 가능

## 백그라운드 처리

계정 삭제에는 다음을 위한 백그라운드 처리가 필요합니다:

1. 영구 삭제 예약
2. 연결된 데이터 정리
3. 외부 시스템 알림 (웹훅)

배포에 백그라운드 작업 프로세서가 포함되어 있는지 확인하세요.

## 모범 사례

1. **사용자 대면 앱에 삭제 활성화** - 사용자 권리 존중
2. **적절한 보존 사용** - 30일이 표준
3. **명확한 UI 제공** - 사용자가 결과를 이해하도록
4. **데이터 내보내기 제공** - 삭제 전 사용자가 데이터 내보내기 가능
5. **삭제 요청 로그** - 감사 규정 준수를 위해
6. **복구 프로세스 테스트** - 지원팀이 계정 복구 가능 확인
7. **지원팀 문서화** - 복구 프로세스에 대해 지원팀 교육
