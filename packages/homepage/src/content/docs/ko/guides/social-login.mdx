Tinyrack Auth는 Google, GitHub, Apple 및 커스텀 OAuth 프로바이더를 통한 소셜 로그인(OAuth 인증)을 지원합니다.

## 지원되는 프로바이더

| 프로바이더 | 타입 | 사전 설정 |
|-----------|------|----------|
| Google | `google` | 예 |
| GitHub | `github` | 예 |
| Apple | `apple` | 예 |
| 커스텀 | `generic_oauth` | 수동 설정 |

## 설정

소셜 로그인 프로바이더는 `oauth_authentication_methods` 섹션에서 설정합니다:

```yaml
oauth_authentication_methods:
  - type: google
    id: google
    enabled: true
    client_id: !env GOOGLE_CLIENT_ID
    client_secret: !env GOOGLE_CLIENT_SECRET
```

## Google 설정

### 1. Google OAuth 자격 증명 생성

1. [Google Cloud Console](https://console.cloud.google.com/)로 이동
2. 프로젝트 생성 또는 선택
3. **APIs & Services** > **Credentials**로 이동
4. **Create Credentials** > **OAuth client ID** 클릭
5. **Web application** 선택
6. 승인된 리디렉션 URI 추가:
   ```
   https://your-domain.com/api/v1/oauth/google/callback
   ```

### 2. Tinyrack Auth 구성

```yaml
oauth_authentication_methods:
  - type: google
    id: google
    enabled: true
    display_name: Google
    client_id: !env GOOGLE_CLIENT_ID
    client_secret: !env GOOGLE_CLIENT_SECRET
    scopes:
      - openid
      - email
      - profile
```

## GitHub 설정

### 1. GitHub OAuth 앱 생성

1. [GitHub Developer Settings](https://github.com/settings/developers)로 이동
2. **New OAuth App** 클릭
3. **Authorization callback URL** 설정:
   ```
   https://your-domain.com/api/v1/oauth/github/callback
   ```

### 2. Tinyrack Auth 구성

```yaml
oauth_authentication_methods:
  - type: github
    id: github
    enabled: true
    display_name: GitHub
    client_id: !env GITHUB_CLIENT_ID
    client_secret: !env GITHUB_CLIENT_SECRET
    scopes:
      - user:email
```

## Apple 설정

### 1. Apple Sign In 자격 증명 생성

1. [Apple Developer Portal](https://developer.apple.com/)로 이동
2. **Certificates, Identifiers & Profiles**로 이동
3. Sign In with Apple 기능이 있는 **App ID** 생성
4. 웹 앱용 **Services ID** 생성
5. **Web Domain** 및 **Return URLs** 구성:
   ```
   https://your-domain.com/api/v1/oauth/apple/callback
   ```

### 2. Tinyrack Auth 구성

```yaml
oauth_authentication_methods:
  - type: apple
    id: apple
    enabled: true
    display_name: Apple
    client_id: !env APPLE_CLIENT_ID
    client_secret: !env APPLE_CLIENT_SECRET
    response_mode: form_post
```

:::note
Apple은 기본적으로 `form_post` 응답 모드를 사용하며, 이는 자동으로 구성됩니다.
:::

## 일반 OAuth 프로바이더

사전 설정되지 않은 커스텀 OAuth 프로바이더용:

```yaml
oauth_authentication_methods:
  - type: generic_oauth
    id: my-provider
    enabled: true
    display_name: My Provider
    icon_url: https://example.com/icon.png
    client_id: !env MY_PROVIDER_CLIENT_ID
    client_secret: !env MY_PROVIDER_CLIENT_SECRET
    authorization_url: https://provider.com/oauth/authorize
    token_url: https://provider.com/oauth/token
    userinfo_url: https://provider.com/api/userinfo
    scopes:
      - openid
      - email
      - profile
    userinfo_mapping:
      id: sub
      email: email
      email_verified: email_verified
      name: name
      picture: avatar_url
```

### 일반 OAuth 필수 필드

| 필드 | 설명 |
|------|------|
| `authorization_url` | OAuth 인증 엔드포인트 |
| `token_url` | 토큰 교환 엔드포인트 |
| `userinfo_url` | 사용자 정보 엔드포인트 (JWT 토큰의 경우 null 가능) |
| `scopes` | 요청할 필수 스코프 |
| `userinfo_mapping` | 프로바이더 응답에서 필드 매핑 |

### Userinfo 매핑

프로바이더별 필드를 표준 필드로 매핑:

```yaml
userinfo_mapping:
  id: sub              # 사용자 식별자
  email: email         # 이메일 주소
  email_verified: verified  # 선택: 이메일 인증 상태
  name: display_name   # 선택: 표시 이름
  picture: avatar      # 선택: 프로필 사진 URL
```

## 이메일 충돌 전략

이미 존재하는 이메일로 소셜 로그인할 때:

```yaml
oauth_authentication_methods:
  - type: google
    id: google
    email_conflict_strategy: auto_link  # 또는 'require_link'
```

| 전략 | 동작 |
|------|------|
| `auto_link` | 기존 계정에 자동으로 연결 |
| `require_link` | 먼저 기존 계정 인증 필요 |

## 공통 옵션

모든 OAuth 프로바이더는 다음 옵션을 지원합니다:

| 필드 | 타입 | 설명 |
|------|------|------|
| `id` | string | 이 프로바이더의 고유 식별자 |
| `type` | string | 프로바이더 타입 |
| `enabled` | boolean | 이 프로바이더 활성화/비활성화 |
| `display_name` | string | UI에 표시되는 이름 |
| `icon_url` | string | UI용 아이콘 URL |
| `client_id` | string | OAuth 클라이언트 ID |
| `client_secret` | string | OAuth 클라이언트 시크릿 |
| `scopes` | string[] | 요청할 OAuth 스코프 |
| `email_conflict_strategy` | string | 이메일 충돌 처리 방법 |

## API 엔드포인트

### OAuth 흐름 시작

```http
GET /api/v1/oauth/:provider/authorize
```

사용자를 OAuth 프로바이더의 인증 페이지로 리디렉션합니다.

### OAuth 콜백

```http
GET /api/v1/oauth/:provider/callback
```

프로바이더로부터의 OAuth 콜백을 처리합니다.

### OAuth 계정 연결 해제

```http
DELETE /api/v1/oauth/:provider
```

사용자 계정과 OAuth 프로바이더 간의 연결을 제거합니다.

### 연결된 계정 목록

```http
GET /api/v1/user/oauth-accounts
```

현재 사용자의 연결된 OAuth 프로바이더 목록을 반환합니다.

## 문제 해결

### "리디렉션 URI 불일치"

OAuth 프로바이더 설정의 콜백 URL이 정확히 일치하는지 확인:
```
https://your-domain.com/api/v1/oauth/{provider}/callback
```

### "유효하지 않은 클라이언트" 오류

클라이언트 ID와 클라이언트 시크릿이 올바른지 확인하세요.

### 이메일이 반환되지 않음

일부 프로바이더는 이메일 접근을 위해 추가 스코프가 필요합니다:
- Google: `email` 스코프
- GitHub: `user:email` 스코프

### Apple Sign In 문제

1. Services ID가 올바르게 구성되었는지 확인
2. 도메인 인증이 완료되었는지 확인
3. `response_mode: form_post`가 설정되었는지 확인
