PKCE(Proof Key for Code Exchange)는 인증 코드를 가로채기 공격으로부터 보호하는 OAuth 2.0의 보안 확장입니다. 퍼블릭 클라이언트(SPA, 모바일 앱)에 필수이며 모든 클라이언트에 권장됩니다.

## PKCE란?

PKCE는 OAuth 흐름에 암호학적 챌린지를 추가합니다:

1. 클라이언트가 랜덤 `code_verifier` 생성
2. 클라이언트가 `code_challenge` = SHA256(code_verifier) 생성
3. 클라이언트가 인증 요청과 함께 `code_challenge` 전송
4. 서버가 챌린지 저장
5. 클라이언트가 토큰 요청과 함께 `code_verifier` 전송
6. 서버가 검증: SHA256(code_verifier) == 저장된 챌린지

## 흐름 다이어그램

```
┌──────────────┐                              ┌──────────────┐
│   클라이언트  │                              │ Tinyrack Auth│
└──────────────┘                              └──────────────┘
       │                                             │
       │  1. code_verifier 생성 (랜덤)               │
       │  2. code_challenge = SHA256(cv) 계산       │
       │                                             │
       │──────── 인증 요청 ─────────────────────────>│
       │    + code_challenge                         │
       │    + code_challenge_method=S256             │
       │                                             │
       │                                             │
       │<─────── 인증 코드 ──────────────────────────│
       │                                             │
       │                                             │
       │──────── 토큰 요청 ─────────────────────────>│
       │    + code_verifier                          │
       │                                             │
       │         서버 검증:                          │
       │         SHA256(code_verifier) == challenge  │
       │                                             │
       │<─────── 액세스 토큰 ────────────────────────│
       │                                             │
```

## 인증 요청

인증 요청에 PKCE 매개변수를 포함합니다:

```http
GET /application/oauth/authorize?
  client_id=my-spa&
  redirect_uri=http://localhost:3000/callback&
  response_type=code&
  scope=openid%20profile%20email&
  state=random-state-value&
  code_challenge=E9Melhoa2OwvFrEMTJguCHaoeK1t8URWbuGJSstw-cM&
  code_challenge_method=S256
```

| 매개변수 | 필수 | 설명 |
|----------|------|------|
| `code_challenge` | 예 | code_verifier의 SHA256 해시를 Base64-URL 인코딩 |
| `code_challenge_method` | 예 | `S256`이어야 함 |

## 토큰 요청

인증 코드 교환 시 code verifier를 포함합니다:

```http
POST /application/oauth/token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code&
code=authorization-code&
redirect_uri=http://localhost:3000/callback&
client_id=my-spa&
code_verifier=dBjftJeZ4CVP-mB92K27uhbUJU1p1r_wW1gFWFOEjXk
```

| 매개변수 | 필수 | 설명 |
|----------|------|------|
| `code_verifier` | 예 | 원본 랜덤 문자열 (43-128자) |

## 구현

### JavaScript/TypeScript

```typescript
// code verifier 생성
function generateCodeVerifier(): string {
  const array = new Uint8Array(32);
  crypto.getRandomValues(array);
  return base64URLEncode(array);
}

// code challenge 생성
async function generateCodeChallenge(verifier: string): Promise<string> {
  const encoder = new TextEncoder();
  const data = encoder.encode(verifier);
  const hash = await crypto.subtle.digest('SHA-256', data);
  return base64URLEncode(new Uint8Array(hash));
}

// Base64 URL 인코딩
function base64URLEncode(buffer: Uint8Array): string {
  return btoa(String.fromCharCode(...buffer))
    .replace(/\+/g, '-')
    .replace(/\//g, '_')
    .replace(/=+$/, '');
}

// 사용
const codeVerifier = generateCodeVerifier();
const codeChallenge = await generateCodeChallenge(codeVerifier);

// 세션 스토리지에 code_verifier 저장
sessionStorage.setItem('code_verifier', codeVerifier);

// 인증 URL 구성
const authUrl = new URL('https://auth.example.com/application/oauth/authorize');
authUrl.searchParams.set('client_id', 'my-spa');
authUrl.searchParams.set('redirect_uri', 'http://localhost:3000/callback');
authUrl.searchParams.set('response_type', 'code');
authUrl.searchParams.set('scope', 'openid profile email');
authUrl.searchParams.set('state', generateState());
authUrl.searchParams.set('code_challenge', codeChallenge);
authUrl.searchParams.set('code_challenge_method', 'S256');

// 인증으로 리디렉션
window.location.href = authUrl.toString();
```

### 토큰 교환

```typescript
// 콜백 페이지에서
const urlParams = new URLSearchParams(window.location.search);
const code = urlParams.get('code');
const codeVerifier = sessionStorage.getItem('code_verifier');

const response = await fetch('https://auth.example.com/application/oauth/token', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/x-www-form-urlencoded',
  },
  body: new URLSearchParams({
    grant_type: 'authorization_code',
    code: code,
    redirect_uri: 'http://localhost:3000/callback',
    client_id: 'my-spa',
    code_verifier: codeVerifier,
  }),
});

const tokens = await response.json();
// { access_token, id_token, refresh_token, ... }
```

## Code Verifier 요구 사항

code verifier는 다음이어야 합니다:

- **길이**: 43-128자
- **문자**: `[A-Z]`, `[a-z]`, `[0-9]`, `-`, `.`, `_`, `~`
- **랜덤**: 암호학적으로 랜덤

## Code Challenge 요구 사항

- **방법**: `S256`만 지원 (`plain` 아님)
- **인코딩**: 패딩 없는 Base64-URL
- **해시**: code verifier의 SHA-256

## 클라이언트 설정

퍼블릭 클라이언트(SPA, 모바일 앱)의 경우 client secret 없이 구성:

```yaml
providers:
  - id: my-spa
    name: My SPA Application
    client_id: my-spa-client-id
    # 퍼블릭 클라이언트에는 client_secret 없음
    redirect_uris:
      - http://localhost:3000/callback
      - https://myapp.example.com/callback
    response_types:
      - code
    grant_types:
      - authorization_code
      - refresh_token
    scope: openid profile email
```

## 보안 고려사항

1. 퍼블릭 클라이언트에 **항상 PKCE 사용**
2. **code_verifier를 안전하게 저장** - 로컬 스토리지가 아닌 세션 스토리지 사용
3. **사용 후 code_verifier 삭제** - 토큰 교환 후 제거
4. **S256 방법 사용** - `plain` 방법은 지원되지 않음
5. **state 매개변수 검증** - CSRF 공격 방지

## 일반적인 오류

### "유효하지 않은 code_verifier"

- code_verifier가 code_challenge 생성에 사용된 것과 일치하는지 확인
- Base64-URL 인코딩이 올바른지 확인 (`+`, `/`, `=` 없음)

### "code_challenge 누락"

- 인증 요청에 code_challenge 포함
- code_challenge_method가 `S256`으로 설정되었는지 확인

### "유효하지 않은 code_challenge_method"

- `S256`만 지원
- `plain` 방법은 보안상의 이유로 허용되지 않음
