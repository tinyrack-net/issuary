OAuth 클라이언트는 사용자 인증을 위해 Tinyrack Auth를 사용하는 애플리케이션입니다. 이 가이드에서는 OAuth 클라이언트를 등록하고 구성하는 방법을 설명합니다.

## OAuth 클라이언트 이해

OAuth 클라이언트는 Tinyrack Auth를 통해 사용자를 인증하려는 모든 애플리케이션입니다. 각 클라이언트에는 다음이 할당됩니다:

- **Client ID** - 고유한 공개 식별자
- **Client Secret** - 서버 측 애플리케이션용 기밀 키
- **Redirect URIs** - 인증 후 허용되는 콜백 URL

## 클라이언트 구성

### 설정 파일을 통해

`config.yaml`에 OAuth 클라이언트를 추가합니다:

```yaml
providers:
  - id: my-web-app
    client_id: my-app-client-id
    client_secret: !env MY_APP_CLIENT_SECRET
    redirect_uris:
      - http://localhost:3000/callback
      - https://myapp.example.com/callback
    scopes:
      - openid
      - profile
      - email
```

### 클라이언트 타입

#### 퍼블릭 클라이언트

시크릿을 안전하게 저장할 수 없는 단일 페이지 애플리케이션(SPA) 또는 모바일 앱용:

```yaml
providers:
  - id: my-spa
    client_id: spa-client-id
    # 퍼블릭 클라이언트에는 client_secret 없음
    redirect_uris:
      - http://localhost:3000/callback
    grant_types:
      - authorization_code
    # PKCE는 퍼블릭 클라이언트에 필수
```

#### 컨피덴셜 클라이언트

시크릿을 안전하게 저장할 수 있는 서버 측 애플리케이션용:

```yaml
providers:
  - id: my-backend
    client_id: backend-client-id
    client_secret: !env BACKEND_CLIENT_SECRET
    redirect_uris:
      - https://api.example.com/auth/callback
    grant_types:
      - authorization_code
      - refresh_token
```

## 스코프

Tinyrack Auth는 다음 스코프를 지원합니다:

| 스코프 | 설명 |
|--------|------|
| `openid` | OIDC에 필수. ID 토큰 반환 |
| `profile` | 사용자의 프로필 정보 (이름 등)에 대한 접근 |
| `email` | 사용자의 이메일 주소에 대한 접근 |
| `offline_access` | 장기 접근을 위한 리프레시 토큰 수신 |

## 인증 흐름

1. 클라이언트가 사용자를 인증 엔드포인트로 리디렉션
2. 사용자가 인증하고 동의 부여
3. Auth 서버가 인증 코드와 함께 리디렉션
4. 클라이언트가 코드를 토큰으로 교환

```
┌──────────┐                              ┌──────────────┐
│ 클라이언트│──(1) 인증 요청 ─────────────>│ Tinyrack Auth│
└──────────┘                              └──────────────┘
      │                                           │
      │                                           v
      │                                    ┌──────────────┐
      │                                    │    사용자    │
      │                                    │    인증      │
      │                                    └──────────────┘
      │                                           │
      │<──────(2) 인증 코드 ──────────────────────┘
      │
      │──────(3) 토큰 요청 ───────────────────────>│
      │<─────(4) 액세스 토큰 + ID 토큰 ────────────┘
```
