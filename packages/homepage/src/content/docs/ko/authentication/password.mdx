비밀번호 인증은 전통적인 이메일/비밀번호 로그인 방식입니다. Tinyrack Auth는 선택적 이메일 인증 및 2단계 인증과 함께 안전한 비밀번호 처리를 제공합니다.

## 설정

```yaml
basic_authentication_methods:
  password:
    enabled: true
    email_verification: true
    second_factor:
      required: false
    totp:
      enabled: true
      issuer: My App
```

## 옵션

| 필드 | 타입 | 기본값 | 설명 |
|------|------|--------|------|
| `enabled` | boolean | `true` | 비밀번호 인증 활성화 |
| `email_verification` | boolean | `true` | 로그인 전 이메일 인증 필요 |
| `second_factor.required` | boolean | `false` | 등록 후 2FA 설정 필요 |
| `totp.enabled` | boolean | `false` | TOTP를 2단계 인증으로 허용 |
| `totp.issuer` | string | `Tinyrack` | 인증 앱에 표시되는 발급자 이름 |

## 이메일 인증

`email_verification`이 활성화되면:

1. 사용자가 이메일과 비밀번호로 등록
2. 인증 이메일 발송
3. 로그인하기 전에 인증 링크를 클릭해야 함
4. 미인증 사용자는 애플리케이션에 접근 불가

### 인증 흐름

```
사용자 등록
     │
     ▼
인증 이메일 발송
     │
     ▼
사용자가 링크 클릭
     │
     ▼
이메일 인증됨 ──► 로그인 허용
```

### 이메일 인증 비활성화

개발 또는 내부 애플리케이션용:

```yaml
basic_authentication_methods:
  password:
    enabled: true
    email_verification: false
```

:::caution
이메일 인증을 비활성화하면 누구나 아무 이메일 주소로 계정을 만들 수 있습니다. 신뢰할 수 있는 환경에서만 비활성화하세요.
:::

## 2단계 인증 요구

등록 후 사용자가 2FA를 설정하도록 강제:

```yaml
basic_authentication_methods:
  password:
    enabled: true
    second_factor:
      required: true
    totp:
      enabled: true
```

`second_factor.required`가 `true`일 때:

1. 사용자가 등록 완료
2. 2FA 설정으로 리디렉션
3. TOTP 또는 패스키를 설정해야 함
4. 그 후에야 애플리케이션에 접근 가능

## 비밀번호 보안

Tinyrack Auth는 업계 표준 비밀번호 보안을 구현합니다:

### 비밀번호 해싱

- **Argon2** 알고리즘 사용 (비밀번호 해싱 대회 우승)
- 자동 솔트 생성
- 설정 가능한 메모리 및 반복 매개변수

### 비밀번호 요구 사항

기본 비밀번호 정책:

- 최소 8자
- 대문자 최소 1개
- 소문자 최소 1개
- 숫자 최소 1개

## API 엔드포인트

### 등록

```http
POST /api/v1/auth/register
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "SecurePassword123"
}
```

### 로그인

```http
POST /api/v1/auth/login
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "SecurePassword123"
}
```

### 비밀번호 재설정 요청

```http
POST /api/v1/auth/password/forgot
Content-Type: application/json

{
  "email": "user@example.com"
}
```

### 비밀번호 재설정

```http
POST /api/v1/auth/password/reset
Content-Type: application/json

{
  "token": "이메일에서-받은-재설정-토큰",
  "password": "NewSecurePassword123"
}
```

## 사용자 비밀번호 관리

인증된 사용자는 비밀번호를 관리할 수 있습니다:

### 비밀번호 업데이트

```http
PUT /api/v1/user/password
Content-Type: application/json

{
  "currentPassword": "OldPassword123",
  "newPassword": "NewPassword456"
}
```

### 비밀번호 추가 (소셜 로그인 사용자용)

소셜 로그인으로 가입한 사용자는 비밀번호를 추가할 수 있습니다:

```http
POST /api/v1/user/password
Content-Type: application/json

{
  "password": "NewPassword123"
}
```

### 비밀번호 제거

다른 인증 방법이 있는 사용자는 비밀번호를 제거할 수 있습니다:

```http
DELETE /api/v1/user/password
Content-Type: application/json

{
  "password": "CurrentPassword123"
}
```

## 모범 사례

1. 프로덕션에서 **이메일 인증 활성화**
2. 민감한 애플리케이션에는 **2FA 요구 고려**
3. 전송 중 자격 증명 보호를 위해 **HTTPS 사용**
4. 무차별 대입 공격 방지를 위한 **속도 제한 구현**
5. 보안 사고를 위한 **로그인 실패 시도 모니터링**
