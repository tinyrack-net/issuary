이메일 인증은 사용자가 등록 시 유효한 이메일 주소를 제공하도록 합니다. 이를 통해 가짜 계정을 방지하고 안전한 비밀번호 복구를 가능하게 합니다.

## 설정

이메일 인증은 인증 방법별로 제어됩니다:

```yaml
basic_authentication_methods:
  password:
    enabled: true
    email_verification: true
  passkey:
    enabled: true
    email_verification: true
```

## 요구 사항

이메일 인증에는 SMTP 설정이 필요합니다:

```yaml
smtp:
  host: smtp.example.com
  port: 587
  secure: true
  user: noreply@example.com
  password: !env SMTP_PASSWORD
  from: noreply@example.com
```

## 인증 흐름

### 비밀번호 등록

```
사용자가 등록 제출
          │
          ▼
계정 생성됨 (미인증)
          │
          ▼
인증 이메일 발송
          │
          ▼
사용자가 링크 클릭
          │
          ▼
이메일 인증됨 ──► 로그인 허용
```

### 패스키 등록

패스키 인증과 이메일 인증을 함께 사용할 때:

1. 사용자가 이메일 주소 입력
2. 인증 이메일 발송
3. 사용자가 인증 링크 클릭
4. 패스키 생성 프롬프트
5. 계정 생성 및 인증됨

## API 엔드포인트

### 이메일 인증

```http
POST /api/v1/auth/email/verify
Content-Type: application/json

{
  "token": "이메일에서-받은-인증-토큰"
}
```

### 인증 이메일 재발송

```http
POST /api/v1/auth/email/resend
Content-Type: application/json

{
  "email": "user@example.com"
}
```

## 이메일 내용

인증 이메일에는 다음이 포함됩니다:

- 이메일 주소를 인증하는 링크
- 만료 알림 (일반적으로 24시간)
- 사용자를 위한 안내

예시 이메일:
```
제목: 이메일 주소를 인증하세요

안녕하세요,

아래 링크를 클릭하여 이메일 주소를 인증하세요:

https://auth.example.com/verify?token=abc123...

이 링크는 24시간 후에 만료됩니다.

계정을 만들지 않으셨다면 이 이메일을 무시하셔도 됩니다.
```

## 토큰 만료

인증 토큰은 설정 가능한 기간 후 만료됩니다:

- 기본값: 24시간
- 일회용: 토큰은 인증 후 무효화됨

## 미인증 사용자 동작

사용자가 이메일을 인증하지 않은 경우:

1. **로그인**: "이메일이 인증되지 않음" 메시지와 함께 차단
2. **비밀번호 재설정**: 여전히 사용 가능 (인증 이메일을 분실한 사용자 도움)
3. **재발송**: 사용자가 새 인증 이메일 요청 가능

## 이메일 인증 비활성화

개발 또는 내부 애플리케이션용:

```yaml
basic_authentication_methods:
  password:
    enabled: true
    email_verification: false
```

:::caution
**보안 경고**: 이메일 인증을 비활성화하면 다음이 가능합니다:
- 가짜 이메일 주소
- 계정 도용
- 비밀번호 복구 불가 (유효한 이메일 없이)

신뢰할 수 있는 환경에서만 비활성화하세요.
:::

## 개발 모드

SMTP 없이 로컬 개발용:

```yaml
smtp:
  test: true  # 이메일을 콘솔에 로그

basic_authentication_methods:
  password:
    enabled: true
    email_verification: true
```

테스트 모드에서는 인증 토큰이 콘솔에 로그됩니다.

## 모범 사례

1. **프로덕션에서 항상 활성화** - 사용자 이메일 인증
2. **SMTP 올바르게 구성** - 이메일 전송 테스트
3. **재발송 옵션 제공** - 사용자가 초기 이메일을 놓칠 수 있음
4. **적절한 만료 설정** - 24시간이 일반적
5. **명확한 오류 메시지** - 사용자가 프로세스를 이해하도록 도움

## 문제 해결

### 인증 이메일이 수신되지 않음

1. 스팸/정크 폴더 확인
2. SMTP 설정 확인
3. 이메일 주소 철자 확인
4. SMTP 서버 로그 검토
5. 발신자 도메인에 적절한 SPF/DKIM 레코드가 있는지 확인

### 토큰 만료됨

사용자는 재발송 엔드포인트를 통해 새 인증 이메일을 요청할 수 있습니다.

### 이미 인증됨

사용자가 이미 인증된 이메일을 인증하려고 하면 로그인으로 안내하는 친절한 메시지를 표시합니다.

## 이메일 템플릿 사용자 지정

이메일 템플릿은 백엔드에서 사용자 지정할 수 있습니다. 기본 템플릿은 이메일 서비스에 있으며 사용자 환경 설정에 따른 다국어 지원을 합니다.
