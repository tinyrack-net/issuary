보안은 중요한 측면이에요. `tinyauth`은 다양한 보안 설정을 제공하여 인증 서버를 안전하게 유지할 수 있도록 도와줘요. 다음은 주요 보안 관련 설정 항목들이에요.

```yaml
app:
  cookie_secret: $COOKIE_SECRET
  jwt_access_token_ttl: 3600
  jwt_refresh_token_ttl: 2592000
  allowed_signup_emails:
    - '*'                        # Allow all emails (public registration)
    # - 'admin@example.com'      # Allow specific email
    # - '*@example.com'          # Allow all emails from domain
  account_deletion: true
```

- `cookie_secret`: 세션 쿠키를 서명하는 데 사용되는 256비트(32바이트) 비밀 키예요. 프로덕션 환경에서는 고유하고 무작위인 값을 생성하는 것이 중요해요. `openssl rand -hex 32` 명령어를 사용하여 생성할 수 있어요. 이 값을 변경하면 기존의 모든 세션이 무효화돼요.
- `jwt_access_token_ttl`: JWT 액세스 토큰의 수명(초 단위)이에요. 액세스 토큰은 짧은 수명을 가지며 API 인증에 사용돼요. 기본값은 3600초(1시간)이며, 권장 900초에서 3600초(15분에서 1시간) 사이로 설정하는 것이 좋아요.
- `jwt_refresh_token_ttl`: JWT 리프레시 토큰의 수명(초 단위)이에요. 리프레시 토큰은 긴 수명을 가지며 새로운 액세스 토큰을 얻는 데 사용돼요. 기본값은 2592000초(30일)이며, 권장 604800초에서 2592000초(7일에서 30일) 사이로 설정하는 것이 좋아요.
- `allowed_signup_emails`: 등록을 허용할 이메일 패턴 목록이에요. 인증 서버에서 누가 새 계정을 생성할 수 있는지 제어해요. 패턴 구문은 다음과 같아요.
  - `*`: 모든 이메일 허용(공개 등록)
  - `user@example.com`: 특정 이메일 주소만 허용
  - `*@example.com`: example.com 도메인의 모든 이메일 허용
  - `*@*.example.com`: example.com의 모든 하위 도메인의 이메일 허용
  여러 패턴을 결합할 수 있어요. 어떤 패턴이라도 일치하면 가입이 허용돼요. 이 목록이 비어 있거나 지정되지 않은 경우 새 가입이 허용되지 않아요.
- `account_deletion`: 사용자가 자신의 계정을 삭제할 수 있는지 여부예요. 활성화되면 사용자는 프로필 설정에서 계정 삭제를 요청할 수 있어요. 보존 기간은 정리 섹션에서 구성돼요. 기본값은 `false`예요.

## Client JWT 토큰 수명 설정

```yaml
app:
  jwt_access_token_ttl: 3600
  jwt_refresh_token_ttl: 2592000
  account_deletion: true
```
