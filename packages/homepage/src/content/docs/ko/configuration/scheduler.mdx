`tinyauth`는 만료된 토큰, 사용된 인증 코드, 삭제된 사용자 데이터 등을 주기적으로 정리하는 내장 스케줄러를 제공해요. 이를 통해 데이터베이스 크기를 관리하고 보안을 유지할 수 있어요.

---

## 스케줄러 설정

```yaml
# config.yaml
scheduler:
  enabled: true
  cron: '0 2 * * *'
```

- `enabled`: 내장 스케줄러를 활성화할지 여부예요. 기본값은 `true`예요.
- `cron`: 정리 작업 실행 주기예요. 표준 5필드 cron 형식(`분 시 일 월 요일`)을 사용해요. 기본값은 `0 2 * * *`(매일 오전 2시)예요.

:::note
Kubernetes 환경에서는 내장 스케줄러 대신 CronJob을 사용하는 것이 좋아요. 이 경우 `enabled: false`로 설정하고, 외부에서 `tinyauth cleanup` CLI 명령을 실행하세요. 자세한 내용은 [Kubernetes 배포 가이드](/ko/deployment/kubernetes)를 참고해 주세요.
:::

## 정리 정책 (`cleanup`)

각 데이터 유형별로 정리 정책을 세밀하게 설정할 수 있어요.

### 기간 형식

정리 정책의 보존 기간(`retention`)은 다음과 같은 형식을 사용해요.

| 형식 | 의미 | 예시 |
|------|------|------|
| `"0"` | 즉시 (보존 기간 없음) | 만료 즉시 삭제 |
| `"30s"` | 초 | 30초 |
| `"30m"` | 분 | 30분 |
| `"24h"` | 시간 | 24시간 |
| `"7d"` | 일 | 7일 |
| `"1y"` | 년 (365일) | 1년 |

---

### 취소된 토큰 (`revoked_tokens`)

```yaml
cleanup:
  revoked_tokens:
    enabled: true
    retention: '0'
```

- `enabled`: 취소된 토큰 정리 활성화 여부예요. 기본값은 `true`예요.
- `retention`: 토큰 만료 후 보존 기간이에요. 기본값은 `"0"` (만료 즉시 삭제)이에요.

### OAuth 인증 코드 (`oauth_codes`)

```yaml
cleanup:
  oauth_codes:
    enabled: true
    consumed_retention: '24h'
```

- `enabled`: 인증 코드 정리 활성화 여부예요. 기본값은 `true`예요.
- `consumed_retention`: 사용된 인증 코드의 보존 기간이에요. 기본값은 `"24h"`예요. 디버깅이나 감사 목적으로 짧은 기간 동안 보존할 수 있어요.

### 이메일 인증 (`email_verifications`)

```yaml
cleanup:
  email_verifications:
    enabled: true
    retention: '0'
```

- `enabled`: 만료된 이메일 인증 토큰 정리 활성화 여부예요. 기본값은 `true`예요.
- `retention`: 만료 후 보존 기간이에요. 기본값은 `"0"`이에요.

### 비밀번호 재설정 (`password_resets`)

```yaml
cleanup:
  password_resets:
    enabled: true
    retention: '0'
```

- `enabled`: 만료된 비밀번호 재설정 토큰 정리 활성화 여부예요. 기본값은 `true`예요.
- `retention`: 만료 후 보존 기간이에요. 기본값은 `"0"`이에요.

### 삭제된 사용자 (`deleted_users`)

```yaml
cleanup:
  deleted_users:
    enabled: true
    retention: '30d'
```

- `enabled`: 소프트 삭제된 사용자의 영구 삭제 활성화 여부예요. 기본값은 `true`예요.
- `retention`: 소프트 삭제 후 영구 삭제까지의 유예 기간이에요. 기본값은 `"30d"` (30일)이에요.

:::note
사용자 삭제는 먼저 소프트 삭제(삭제 표시)된 후, 보존 기간이 지나면 관련된 모든 데이터(OAuth 계정, TOTP, 패스키, 동의 기록 등)와 함께 영구 삭제돼요. 이 기능은 `app.account_deletion`이 `true`일 때만 동작해요.
:::

### JWT 키 순환 (`jwt_keys`)

```yaml
cleanup:
  jwt_keys:
    enabled: true
```

- `enabled`: 정리 작업 실행 시 JWT 키 순환을 함께 수행할지 여부예요. 기본값은 `true`예요. 실제 순환 동작은 `app.jwt_key_rotation_enabled`가 `true`일 때만 수행돼요.

---

## 전체 예시

```yaml
# config.yaml
scheduler:
  enabled: true
  cron: '0 2 * * *'

cleanup:
  revoked_tokens:
    enabled: true
    retention: '0'
  oauth_codes:
    enabled: true
    consumed_retention: '24h'
  email_verifications:
    enabled: true
    retention: '0'
  password_resets:
    enabled: true
    retention: '0'
  deleted_users:
    enabled: true
    retention: '30d'
  jwt_keys:
    enabled: true
```

## CLI 명령어

스케줄러와 별개로, CLI를 통해 수동으로 정리 작업을 실행할 수도 있어요.

```bash
# 정리 작업 실행
tinyauth cleanup

# 실제 삭제 없이 대상만 확인 (드라이 런)
tinyauth cleanup --dry-run

# 상세 진행 상황 출력
tinyauth cleanup --verbose

# 커스텀 설정 파일 사용
tinyauth cleanup -c /path/to/config.yaml
```
