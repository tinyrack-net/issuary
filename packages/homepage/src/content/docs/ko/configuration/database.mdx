Tinyauth는 여러 데이터베이스 백엔드를 지원합니다. 배포 요구 사항에 맞는 것을 선택하세요.

## 지원되는 데이터베이스

| 타입 | 사용 사례 |
|------|----------|
| SQLite | 개발, 소규모 배포 |
| PostgreSQL | 프로덕션, 확장 가능한 배포 |
| Memory | 테스트, CI/CD 파이프라인 |

## SQLite 설정

SQLite는 기본 데이터베이스로, 개발 및 소규모 배포에 적합합니다.

```yaml
database:
  type: sqlite
  path: ./data/auth.db
```

| 필드 | 타입 | 기본값 | 설명 |
|------|------|--------|------|
| `type` | string | - | `sqlite`이어야 함 |
| `path` | string | `test.db` | SQLite 데이터베이스 파일 경로 |

### SQLite 모범 사례

- 프로덕션에서는 절대 경로 사용
- 디렉토리가 존재하고 쓰기 가능한지 확인
- 데이터베이스 파일 백업 전략 고려

```yaml
# 프로덕션 예제
database:
  type: sqlite
  path: /var/lib/tinyauth/auth.db
```

## PostgreSQL 설정

PostgreSQL은 고가용성과 확장성이 필요한 프로덕션 배포에 권장됩니다.

```yaml
database:
  type: postgres
  host: localhost
  port: 5432
  user: auth_user
  password: !env DB_PASSWORD
  name: tinyauth
```

| 필드 | 타입 | 기본값 | 설명 |
|------|------|--------|------|
| `type` | string | - | `postgres`이어야 함 |
| `host` | string | `localhost` | 데이터베이스 서버 호스트명 |
| `port` | number | `5432` | 데이터베이스 서버 포트 |
| `user` | string | `test` | 데이터베이스 사용자명 |
| `password` | string | `test` | 데이터베이스 비밀번호 |
| `name` | string | `test` | 데이터베이스 이름 |

### PostgreSQL 설정 방법

1. 데이터베이스와 사용자 생성:

```sql
CREATE USER auth_user WITH PASSWORD 'your-secure-password';
CREATE DATABASE tinyauth OWNER auth_user;
```

2. `config.yaml` 구성:

```yaml
database:
  type: postgres
  host: localhost
  port: 5432
  user: auth_user
  password: !env DB_PASSWORD
  name: tinyauth
```

3. 환경 변수 설정:

```bash
export DB_PASSWORD=your-secure-password
```

### 연결 문자열 형식

설정은 내부적으로 연결 문자열로 변환됩니다:

```
postgresql://auth_user:password@localhost:5432/tinyauth
```

## 인메모리 데이터베이스

인메모리 데이터베이스는 테스트 및 CI/CD 파이프라인에 유용합니다. 서버가 중지되면 모든 데이터가 손실됩니다.

```yaml
database:
  type: memory
```

| 필드 | 타입 | 설명 |
|------|------|------|
| `type` | string | `memory`이어야 함 |

### 테스트 예제

```yaml
# test-config.yaml
database:
  type: memory

basic_authentication_methods:
  password:
    enabled: true
    email_verification: false  # 테스트용으로 비활성화
```

## 데이터베이스 마이그레이션

Tinyauth는 시작 시 자동으로 데이터베이스 스키마 마이그레이션을 관리합니다. 수동 마이그레이션 명령이 필요하지 않습니다.

### 마이그레이션 동작

1. 첫 번째 시작 시 스키마가 자동으로 생성됩니다
2. 이후 시작 시 대기 중인 마이그레이션이 적용됩니다
3. 마이그레이션은 지원되는 경우 트랜잭션으로 처리됩니다

## 환경별 설정

### 개발

```yaml
database:
  type: sqlite
  path: ./data/dev.db
```

### 테스트

```yaml
database:
  type: memory
```

### 프로덕션

```yaml
database:
  type: postgres
  host: !env DB_HOST
  port: 5432
  user: !env DB_USER
  password: !env DB_PASSWORD
  name: !env DB_NAME
```

## Docker Compose 예제

```yaml
version: '3.8'

services:
  auth:
    image: tinyauth
    environment:
      - DB_HOST=postgres
      - DB_USER=auth_user
      - DB_PASSWORD=secret
      - DB_NAME=tinyauth
    depends_on:
      - postgres

  postgres:
    image: postgres:16
    environment:
      - POSTGRES_USER=auth_user
      - POSTGRES_PASSWORD=secret
      - POSTGRES_DB=tinyauth
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:
```
