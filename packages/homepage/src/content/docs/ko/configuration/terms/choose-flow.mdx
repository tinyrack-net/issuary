---
title: 플로우 선택하기
description: 약관의 암시적 또는 명시적 동의 플로우 구성하기
---

약관 동의는 복잡한 주제에요. 서비스가 운영되는 지역의 법률과 요구에 따라 다른 절차가 필요할 수 있어요.
이를 위해 `tinyauth`에서는 **명시적(explicit) 동의 플로우**와 **암시적(implicit) 동의 플로우**를 제공하며 이 중 하나를 선택하거나 둘을 조합해 사용할 수 있어요. 

## 암시적 동의

먼저 **암시적 동의**는, 가입 행위 자체를 서비스 이용에 대한 **암시적** 동의로 간주하여, 가입과 약관 동의가 동시에 이루어짐을 의미해요.
**"계속하면 서비스 이용에 동의한 것으로 간주됩니다"** 라는 문구를 본 적이 있다면 암시적 플로우를 진행한거예요.
이는 사용자에게 귀찮은 절차를 생략할 수 있다는 장점이 있지만 미국처럼 법률적으로 이를 허용하는 지역에서만 사용할 수 있어요.

## 명시적 동의

**명시적 동의**는 사용자가 직접적인 행동을 통해 약관 동의를 진행한다는 것을 의미해요.
회원 가입시 **약관 동의 체크박스**를 본 적이 있다면 명시적 플로우를 진행한거예요.
이는 유럽의 GDPR, 한국의 개인정보보호법 등 법률적으로 이 절차를 반드시 요구하는 경우 사용할 수 있어요.

---

## 플로우 비교

| | 명시적(explicit) 플로우 | 암시적(implicit) 플로우 |
|---|---|---|
| **동의 방식** | 각 약관에 대해 체크박스를 직접 선택 | 가입 행위 자체가 동의로 간주 |
| **UI 표시** | 체크박스 목록 | 안내 문구 (예: "계속하면 약관에 동의하는 것으로 간주합니다") |
| **선택적 동의** | 지원 (`required: false`) | 미지원 (모든 항목이 일괄 동의) |
| **동의 기록** | 항목별 개별 기록 | 가입 시 자동 일괄 기록 |
| **설정 키** | `consent_mode: explicit` | `consent_mode: implicit` + `app.signup_implicit_terms` |

---

## 어떤 플로우를 선택해야 하나요?

### 명시적 플로우가 필요한 경우

다음과 같은 상황에서는 [명시적 플로우](/ko/configuration/terms/explicit-flow)를 사용하세요.

- **GDPR (EU 일반 데이터 보호 규정)** 적용 대상인 경우. GDPR은 개인정보 처리에 대한 동의가 자유롭고, 구체적이며, 정보에 입각한 명확한 동의여야 한다고 요구해요.
- **한국 개인정보보호법** 적용 대상인 경우. 한국에서는 개인정보 수집·이용에 대한 별도 동의를 받아야 하며, 필수 항목과 선택 항목을 구분하여 동의를 받아야 해요.
- **마케팅 수신 동의** 등 선택적 동의 항목을 제공해야 하는 경우. 명시적 플로우만 `required: false` 옵션을 지원해요.
- 사용자에게 각 약관에 대한 **개별 동의 내역**을 명확히 기록해야 하는 경우.

```yaml
# config.yaml
terms:
  - id: tos
    required: true
    consent_mode: explicit
    version: "1.0.0"
    content:
      ko:
        title: 이용약관
        type: link
        content: https://example.com/ko/terms

  - id: privacy
    required: true
    consent_mode: explicit
    version: "1.0.0"
    content:
      ko:
        title: 개인정보 처리방침
        type: link
        content: https://example.com/ko/privacy

  - id: marketing
    required: false
    consent_mode: explicit
    version: "1.0.0"
    content:
      ko:
        title: 마케팅 수신 동의
        type: text
        content: 마케팅 이메일 및 프로모션 알림을 수신하시겠어요?
```

### 암시적 플로우가 적합한 경우

다음과 같은 상황에서는 [암시적 플로우](/ko/configuration/terms/implicit-flow)를 사용하세요.

- **미국** 등 명시적 체크박스 동의가 법적으로 요구되지 않는 지역에서 서비스하는 경우. 미국에서는 "계속하면 약관에 동의하는 것으로 간주합니다"와 같은 안내 문구만으로도 유효한 동의로 인정돼요.
- 가입 과정을 최대한 **간결하게** 유지하고 싶은 경우. 체크박스 없이 안내 문구만 표시하므로 사용자 경험이 더 매끄러워요.
- 모든 약관에 대해 **일괄 동의**를 받아도 되는 경우.

```yaml
# config.yaml
terms:
  - id: tos
    required: true
    consent_mode: implicit
    version: "1.0.0"
    content:
      ko:
        title: 이용약관
        type: link
        content: https://example.com/ko/terms

  - id: privacy
    required: true
    consent_mode: implicit
    version: "1.0.0"
    content:
      ko:
        title: 개인정보 처리방침
        type: link
        content: https://example.com/ko/privacy

app:
  signup_implicit_terms:
    ko: >-
      계속하면 <a href="https://example.com/ko/terms" class="link">이용약관</a>
      및 <a href="https://example.com/ko/privacy" class="link">개인정보 처리방침</a>에
      동의하는 것으로 간주해요.
```

## 두 플로우 혼합하기

명시적 플로우와 암시적 플로우를 조합하여 사용할 수도 있어요. 예를 들어, 이용약관과 개인정보 처리방침은 암시적으로 처리하고, 마케팅 수신 동의처럼 선택적 항목만 명시적으로 받을 수 있어요.

```yaml
# config.yaml
terms:
  # 암시적 동의 - 가입 시 자동 동의
  - id: tos
    required: true
    consent_mode: implicit
    version: "1.0.0"
    content:
      ko:
        title: 이용약관
        type: link
        content: https://example.com/ko/terms

  - id: privacy
    required: true
    consent_mode: implicit
    version: "1.0.0"
    content:
      ko:
        title: 개인정보 처리방침
        type: link
        content: https://example.com/ko/privacy

  # 명시적 동의 - 체크박스로 개별 동의
  - id: marketing
    required: false
    consent_mode: explicit
    version: "1.0.0"
    content:
      ko:
        title: 마케팅 수신 동의
        type: text
        content: 마케팅 이메일 및 프로모션 알림을 수신하시겠어요?

app:
  signup_implicit_terms:
    ko: >-
      계속하면 <a href="https://example.com/ko/terms" class="link">이용약관</a>
      및 <a href="https://example.com/ko/privacy" class="link">개인정보 처리방침</a>에
      동의하는 것으로 간주해요.
```

이 구성에서 회원가입 화면에는 다음과 같이 표시돼요.

1. 암시적 동의 안내 문구
2. "그리고" 구분선
3. 마케팅 수신 동의 체크박스

:::note
혼합 사용 시에도 `app.signup_implicit_terms` 안내 문구는 반드시 설정해야 해요. 암시적 약관 항목이 있는데 안내 문구가 없으면 사용자에게 동의 사실이 표시되지 않아요.
:::

## 지역별 권장 구성

### EU / EEA (GDPR)

GDPR은 동의의 명확성과 구체성을 강조해요. 모든 약관에 대해 명시적 플로우를 사용하는 것을 권장해요.

- 이용약관: `consent_mode: explicit`, `required: true`
- 개인정보 처리방침: `consent_mode: explicit`, `required: true`
- 마케팅 수신: `consent_mode: explicit`, `required: false`

### 한국

개인정보보호법에 따라 개인정보 수집·이용 동의는 명시적으로 받아야 하며, 필수와 선택 항목을 구분해야 해요.

- 이용약관: `consent_mode: explicit`, `required: true`
- 개인정보 처리방침: `consent_mode: explicit`, `required: true`
- 마케팅 수신: `consent_mode: explicit`, `required: false`

### 미국

명시적 체크박스 동의가 필수는 아니므로 암시적 플로우를 사용할 수 있어요. 단, 마케팅 동의는 명시적으로 받는 것이 일반적이에요.

- 이용약관: `consent_mode: implicit`
- 개인정보 처리방침: `consent_mode: implicit`
- 마케팅 수신: `consent_mode: explicit`, `required: false`

:::caution
이 가이드는 일반적인 참고 사항이에요. 실제 서비스에 적용할 때는 반드시 법률 전문가의 자문을 받으세요.
:::
