Tinyrack Auth는 민감한 설정 값에 환경 변수를 사용합니다. 이 페이지에서는 지원되는 모든 환경 변수와 사용 방법을 설명합니다.

## 설정에서 환경 변수 사용

환경 변수를 참조하려면 `!env` YAML 태그를 사용합니다:

```yaml
app:
  cookie_secret: !env COOKIE_SECRET

database:
  password: !env DB_PASSWORD

smtp:
  password: !env SMTP_PASSWORD
```

## 설정 경로

| 변수 | 기본값 | 설명 |
|------|--------|------|
| `CONFIG_PATH` | `/opt/config.yaml` | 설정 파일 경로 |

```bash
CONFIG_PATH=/etc/tinyrack/config.yaml pnpm start
```

## 필수 변수

프로덕션 배포에 일반적으로 필요한 변수입니다:

| 변수 | 설명 |
|------|------|
| `COOKIE_SECRET` | 세션 쿠키용 비밀 키 (최소 16자) |
| `DB_PASSWORD` | 데이터베이스 비밀번호 (PostgreSQL 사용 시) |
| `SMTP_PASSWORD` | SMTP 서버 비밀번호 |

## 데이터베이스 변수

PostgreSQL 사용 시:

| 변수 | 설명 |
|------|------|
| `DB_HOST` | 데이터베이스 서버 호스트명 |
| `DB_PORT` | 데이터베이스 서버 포트 |
| `DB_USER` | 데이터베이스 사용자명 |
| `DB_PASSWORD` | 데이터베이스 비밀번호 |
| `DB_NAME` | 데이터베이스 이름 |

```yaml
database:
  type: postgres
  host: !env DB_HOST
  port: 5432
  user: !env DB_USER
  password: !env DB_PASSWORD
  name: !env DB_NAME
```

## OAuth 프로바이더 변수

소셜 로그인 프로바이더용:

### Google

| 변수 | 설명 |
|------|------|
| `GOOGLE_CLIENT_ID` | Google OAuth 클라이언트 ID |
| `GOOGLE_CLIENT_SECRET` | Google OAuth 클라이언트 시크릿 |

### GitHub

| 변수 | 설명 |
|------|------|
| `GITHUB_CLIENT_ID` | GitHub OAuth 클라이언트 ID |
| `GITHUB_CLIENT_SECRET` | GitHub OAuth 클라이언트 시크릿 |

### Apple

| 변수 | 설명 |
|------|------|
| `APPLE_CLIENT_ID` | Apple OAuth 클라이언트 ID |
| `APPLE_CLIENT_SECRET` | Apple OAuth 클라이언트 시크릿 |

## OAuth 클라이언트 변수

애플리케이션의 OAuth 클라이언트용:

| 변수 | 설명 |
|------|------|
| `MY_APP_CLIENT_SECRET` | OAuth 애플리케이션의 클라이언트 시크릿 |

```yaml
providers:
  - id: my-app
    client_id: my-app-client-id
    client_secret: !env MY_APP_CLIENT_SECRET
```

## 사전 설정된 사용자 변수

설정 기반 사용자 계정용:

| 변수 | 설명 |
|------|------|
| `ADMIN_PASSWORD` | 설정에 정의된 관리자 사용자 비밀번호 |

```yaml
users:
  - id: admin
    email: admin@example.com
    password: !env ADMIN_PASSWORD
```

## 환경 파일

로컬 개발을 위해 프로젝트 루트에 `.env` 파일을 생성합니다:

```bash
# .env
COOKIE_SECRET=your-super-secret-cookie-key-here

# 데이터베이스
DB_HOST=localhost
DB_PORT=5432
DB_USER=auth_user
DB_PASSWORD=your-db-password
DB_NAME=tinyrack_auth

# SMTP
SMTP_PASSWORD=your-smtp-password

# OAuth 프로바이더
GOOGLE_CLIENT_ID=your-google-client-id
GOOGLE_CLIENT_SECRET=your-google-client-secret
GITHUB_CLIENT_ID=your-github-client-id
GITHUB_CLIENT_SECRET=your-github-client-secret

# 애플리케이션 클라이언트
MY_APP_CLIENT_SECRET=your-app-client-secret

# 관리자 사용자
ADMIN_PASSWORD=your-admin-password
```

:::caution
`.env` 파일을 버전 관리에 커밋하지 마세요. `.gitignore` 파일에 `.env`를 추가하세요.
:::

## Docker 환경

Docker 컨테이너에 환경 변수 전달:

```bash
docker run -d \
  -e COOKIE_SECRET=your-secret \
  -e DB_PASSWORD=your-db-password \
  -e SMTP_PASSWORD=your-smtp-password \
  tinyrack/auth
```

또는 env 파일 사용:

```bash
docker run -d --env-file .env tinyrack/auth
```

## Docker Compose

```yaml
version: '3.8'

services:
  auth:
    image: tinyrack/auth
    environment:
      - COOKIE_SECRET=${COOKIE_SECRET}
      - DB_HOST=postgres
      - DB_USER=auth_user
      - DB_PASSWORD=${DB_PASSWORD}
      - DB_NAME=tinyrack_auth
      - SMTP_PASSWORD=${SMTP_PASSWORD}
```

## Kubernetes Secrets

Kubernetes 시크릿 생성:

```bash
kubectl create secret generic tinyrack-auth-secrets \
  --from-literal=COOKIE_SECRET=your-secret \
  --from-literal=DB_PASSWORD=your-db-password \
  --from-literal=SMTP_PASSWORD=your-smtp-password
```

배포에서 참조:

```yaml
apiVersion: apps/v1
kind: Deployment
spec:
  template:
    spec:
      containers:
        - name: auth
          envFrom:
            - secretRef:
                name: tinyrack-auth-secrets
```

## 보안 모범 사례

1. **강력한 시크릿 사용**: 시크릿에 랜덤 문자열 생성
   ```bash
   openssl rand -base64 32
   ```

2. **정기적으로 시크릿 로테이션**: 주기적으로 시크릿 업데이트

3. **접근 제한**: 권한이 있는 담당자만 시크릿에 접근

4. **시크릿 관리 사용**: HashiCorp Vault, AWS Secrets Manager, Kubernetes Secrets 같은 도구 고려

5. **접근 감사**: 민감한 설정에 대한 접근 로그 및 모니터링
