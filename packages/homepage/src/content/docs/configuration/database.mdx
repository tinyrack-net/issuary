Tinyrack Auth supports multiple database backends. Choose the one that best fits your deployment needs.

## Supported Databases

| Type | Use Case |
|------|----------|
| SQLite | Development, small deployments |
| PostgreSQL | Production, scalable deployments |
| Memory | Testing, CI/CD pipelines |

## SQLite Configuration

SQLite is the default database, ideal for development and small deployments.

```yaml
database:
  type: sqlite
  path: ./data/auth.db
```

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `type` | string | - | Must be `sqlite` |
| `path` | string | `test.db` | Path to the SQLite database file |

### SQLite Best Practices

- Use an absolute path in production
- Ensure the directory exists and is writable
- Consider backup strategies for the database file

```yaml
# Production example
database:
  type: sqlite
  path: /var/lib/tinyrack-auth/auth.db
```

## PostgreSQL Configuration

PostgreSQL is recommended for production deployments requiring high availability and scalability.

```yaml
database:
  type: postgres
  host: localhost
  port: 5432
  user: auth_user
  password: !env DB_PASSWORD
  name: tinyrack_auth
```

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `type` | string | - | Must be `postgres` |
| `host` | string | `localhost` | Database server hostname |
| `port` | number | `5432` | Database server port |
| `user` | string | `test` | Database username |
| `password` | string | `test` | Database password |
| `name` | string | `test` | Database name |

### PostgreSQL Setup

1. Create the database and user:

```sql
CREATE USER auth_user WITH PASSWORD 'your-secure-password';
CREATE DATABASE tinyrack_auth OWNER auth_user;
```

2. Configure your `config.yaml`:

```yaml
database:
  type: postgres
  host: localhost
  port: 5432
  user: auth_user
  password: !env DB_PASSWORD
  name: tinyrack_auth
```

3. Set the environment variable:

```bash
export DB_PASSWORD=your-secure-password
```

### Connection String Format

The configuration is internally converted to a connection string:

```
postgresql://auth_user:password@localhost:5432/tinyrack_auth
```

## In-Memory Database

The in-memory database is useful for testing and CI/CD pipelines. All data is lost when the server stops.

```yaml
database:
  type: memory
```

| Field | Type | Description |
|-------|------|-------------|
| `type` | string | Must be `memory` |

### Testing Example

```yaml
# test-config.yaml
database:
  type: memory

basic_authentication_methods:
  password:
    enabled: true
    email_verification: false  # Disable for testing
```

## Database Migrations

Tinyrack Auth automatically manages database schema migrations on startup. No manual migration commands are required.

### Migration Behavior

1. On first startup, the schema is created automatically
2. On subsequent startups, pending migrations are applied
3. Migrations are transactional where supported

## Environment-Specific Configuration

### Development

```yaml
database:
  type: sqlite
  path: ./data/dev.db
```

### Testing

```yaml
database:
  type: memory
```

### Production

```yaml
database:
  type: postgres
  host: !env DB_HOST
  port: 5432
  user: !env DB_USER
  password: !env DB_PASSWORD
  name: !env DB_NAME
```

## Docker Compose Example

```yaml
version: '3.8'

services:
  auth:
    image: tinyrack/auth
    environment:
      - DB_HOST=postgres
      - DB_USER=auth_user
      - DB_PASSWORD=secret
      - DB_NAME=tinyrack_auth
    depends_on:
      - postgres

  postgres:
    image: postgres:16
    environment:
      - POSTGRES_USER=auth_user
      - POSTGRES_PASSWORD=secret
      - POSTGRES_DB=tinyrack_auth
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:
```
